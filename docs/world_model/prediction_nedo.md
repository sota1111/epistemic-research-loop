## 0. なぜ NEDO なのか

corpus の 38 コンペは**全部「予測値を提出する」コンペ**である。NEDO は
**アルゴリズム(ソースコード)を提出し、評価基盤がシミュレーションを回して採点する。**
符号化規則 §3 が「`submission_type` は学習に使わない。**NEDO を問題クラス外テストへ掛けるときに使う**」
と書いていたのは、この場面のことである。

## 1. context の符号化 —— **これ自体が不確かである**

| 特徴 | 値 | 根拠と、その弱いところ |
| --- | ---: | --- |
| `decomposable_metric` | **1** | 採点が fill / cog / placement / stability に分解でき、**その分解が上位差になる**(重みは非公開)。規則の定義にそのまま当たる |
| `entity` | **1** | 規則の定義は「同一 entity が**複数行に跨って**現れる」。NEDO に行は無い。**同一コンテナが多数の配置ステップに跨る**を entity と読んだ、**類推である** |
| `temporal` | **0 と 1 の両方に読める** | 規則は「時間順序が予測対象の一部」。NEDO は課題型 `001` が**到着順**(`look_ahead=10`)で、順序が解法の一部である。一方 `000` はオフライン並べ替え可で時間構造は無い。**同一コンペに両方ある** |

**[引き継ぎ書](../v050_course_correction.md) §7 は `temporal=0 / entity=1 / decomposable=1` と
書いていたが、その 3 つのうち確かなのは 1 つだけである。**

**対処:** 両方の読みで予測を出した。**点予測は完全に一致した**(下記)。
したがって以下の登録は `temporal` の読みに依存しない。**依存していたら、
先に符号化規則を直すべきだった。**

## 2. **corpus は NEDO の context を張っていない**(いちばん重要)

3 つの二値特徴で 8 セル。38 コンペが観測したのは **6 セル**である。

| セル (temporal, entity, decomposable) | コンペ数 |
| --- | ---: |
| (0,0,0) | 14 |
| (1,1,0) | 13 |
| (0,1,0) | 5 |
| (0,0,1) | 4 |
| (1,0,0) | 1 |
| (1,1,1) | 1(M5 のみ) |
| **(0,1,1) ← NEDO** | **0** |
| (1,0,1) | 0 |

**NEDO のセルは空である。**よって条件付き分布は全体分布へ落ち、
**「context 条件付けの予測」は「チェックリストの予測」と 1 ビットも違わない。**

`temporal=1` と読んだ場合のセル (1,1,1) にも **1 コンペ(M5)しか無く**、
縮約 `k0=5` の下では全体分布に支配される。**やはり点予測は同一**である。

> **NEDO は context 条件付けのテストにならない。**この装置でテストできるのは
> **チェックリストのほう**である。
>
> これは装置クラス A3(**課題セットが張っていない軸は装置の盲点になる**)と
> **同型**である。今回張っていないのは corpus の側で、盲点は世界モデルの側にある。

2. **SED(Solution / Error Diversity)は `p_minus` 0.33。**「多様性を持て」は corpus で
   3 回に 1 回は逆に働いている

## 5. 判定(事前登録)

**NEDO の符号化は、[coding_rules.md](coding_rules.md) §1〜2 の規則をそのまま使う。**
根拠にできるのは NEDO 側リポジトリの一次記録(`docs/programme.md`・`docs/round4_5.md`・
実測の JSON)であって、記憶や本文書ではない。

報告する量:

| # | 量 | なぜ |
| ---: | --- | --- |
| 1 | **13 状態の Hamming 一致率** | 一次版と同じ形。ただし下の注意を必ず併記する |
| 2 | **`+1` の再現数**(真に決定的な状態のうち何件を当てたか) | **これを主要指標とする。**一致率は 0 の多数派に支配される([結果](results.md) §2.1) |
| 3 | **`−1` の有無** | 反例が出たら、それは corpus が持っていない情報である |
| 4 | **チェックリストとの差** | **NEDO では定義上 0 である**(§2)。0 でなければ実装の誤り |

**判定基準:**

- **予測が当たっても、それは context 条件付けの証拠にならない**(§2。予測はチェックリストと同一)。
  当たった場合に言えるのは「**winner corpus の全体頻度が、問題クラスを跨いで転移した**」だけである
- **`+1` の再現が 4 分の 1 以下**(= 予測どおり RMC だけ)なら、
  **「38 コンペのチェックリストは、この問題クラスへ転移しなかった」と記録する。**
  これは失敗ではなく結果である
- **どちらでも、context 条件付けの当否は測れない。**測れるようにするには corpus に
  (0,1,1) のコンペが要る —— [結果](results.md) §4 の 2(cv / nlp に効く特徴)と同じく、
  **corpus の被覆の問題**である
