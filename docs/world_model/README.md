## 0. 一行で

**「どのコンペで、どの研究状態が勝敗を決めたか」の、構造属性で条件付けた分布**である。
目標値ベクトルではない。チェックリストでもない。**点ラベルへ潰した時点で反例が消え、チェックリストと区別できなくなる。**

## 1. 何を符号化したか —— 値ではなく決定性

write-up から「勝者の validation_fidelity は 0.82 だった」は**復元できない。**
復元できるのは「**この勝ち方を決めたのはどの状態か**」である。よって各セルに 3 値を置いた。

| 値 | 意味 |
| ---: | --- |
| `+1` | **決定的だった** —— 上位到達の主要因として本文が明示している |
| `0` | **記録なし** —— 言及が無い。**「重要でなかった」ではない**(write-up の欠落と区別できない) |
| `−1` | **反例** —— 「その状態が高くなければ勝てない」を**反証する**証拠として挙げられている |

**`−1` がこのモデルの要である。**これが無ければ、出力は「上位者がやっていたことの一覧」=
チェックリストになる。反例は 6 件:Mercari(SED・RMC)/ DSTL(SED)/ Bengali.AI(RMC)/
Planet Amazon(PB)/ Quora(PB)。

素材は `research_models.md` §44 の **38 コンペ × 13 状態 = 494 セル**。

## 2. 何で条件付けたか —— domain ではなく構造属性

**domain は特徴に使えない。**leave-one-domain-out で保留する軸だからである。
仕様 §247 が禁じているのは「tabular fraud の習慣を CV コンペへ押しつけること」なので、
**domain ではなく構造で条件付ける。**n=38 なので 3 特徴に固定した。

| 特徴 | 定義 |
| --- | --- |
| `temporal` | 時間順序が予測対象の一部、または train/test が時間で分かれる |
| `entity` | 同一 entity が複数行に跨って現れる |
| `decomposable_metric` | 指標が subgroup / class / 階層へ分解でき、その分解が上位差になりうる |

当てはめは条件付き頻度を全体頻度へ **`k0 = 5`** で縮約する(prior strength を low に固定、§18)。

## 3. 検証結果 —— 事前登録した基準は満たした

leave-one-domain-out、対応ありブートストラップ 10,000 回。

| 予測子 | 一致率 |
| --- | ---: |
| チェックリスト(context を無視した多数決) | 0.8462 |
| **context 条件付け** | **0.8745** |
| 差 | **+0.0283**、95% 区間 **[+0.0121, +0.0466]** |

**区間が 0 をまたがない。**「Preferred State は固定ベクトルではなく context 条件付き分布」
という §247 の主張は、**保留した domain に対して成立した。**

## 4. この数字を大きく読んではいけない 4 つの理由

1. **一致率は多数派に支配されている。**494 セル中 **410 件(83.0%)が `0`**。
   「どれも決定的でない」と答えるだけで 0.83 が出る
2. **決定的な状態は過半を落としている。**真に `+1` の 78 セルの再現は
   **31/78**(チェックリストは 22/78)
3. **反例を 1 件も再現できない。**6 セルの `−1` に対し **0/6**
4. **利得は時間構造のある 3 domain からしか出ていない**

| domain | n | context | チェックリスト | 差 |
| --- | ---: | ---: | ---: | ---: |
| forecasting | 6 | 0.910 | 0.833 | **+0.077** |
| tabular | 7 | 0.824 | 0.758 | **+0.066** |
| recsys | 3 | 0.897 | 0.846 | **+0.051** |
| cv | 10 | 0.885 | 0.885 | 0.000 |
| nlp | 9 | 0.863 | 0.863 | 0.000 |
| other | 3 | 0.897 | 0.897 | 0.000 |

**cv / nlp / other では予測がチェックリストと完全に一致した** —— 3 特徴のうち 2 つが
これらの domain でほぼ定数になり、条件付けが働かないためである。

## 5. 反例を再現しようとして、落ちた

理由 3 は重い。**チェックリスト化を防ぐ唯一の仕掛けが、当てはめで消える。**
そこで決定性(`P(言及)`)と必要性の向き(`P(−1 | 言及)`)を分けた 2 部モデルを
[**当てはめ前に事前登録**](coding_rules_v2_counterexample.md)して走らせた。

| | 一致率 | 平均対数損失 | `−1` 再現 | `+1` 再現 |
| --- | ---: | ---: | ---: | ---: |
| context 条件付け(一次) | 0.8745 | 0.4318 | 0/6 | 31/78 |
| 2 部モデル | 0.8664 | 0.4420 | **0/6** | 24/78 |
| 差 | **−0.0081** [−0.0223, +0.0061] | **+0.0103** [+0.0027, +0.0174] | | |

**事前登録した 2 基準とも不合格 → 点予測形式としては不採用。**
対数損失の区間は 0 をまたがない ——「反例の再現と一致率のトレードオフ」ではなく、
**再パラメータ化自体が負けている。**

**原因は理由 4 と同じ 1 つの穴である。`−1` の 6 セルは全部 cv / nlp にあり、
そこでは context 特徴が定数**なので、セルが反例を分離しない。

### 採ったのは「分布に `P(−1)` を持たせる形」

| 状態 | 観測 `+1` / `−1` | `P(言及)` | **`P(−1 \| 言及)`** |
| --- | ---: | ---: | ---: |
| **Performance Belief** | 0 / 2 | 0.075 | **0.75** |
| **Solution / Error Diversity** | 5 / 2 | 0.200 | **0.33** |
| Representation / Model Coverage | 22 / 2 | 0.625 | 0.12 |
| Validation Fidelity | 11 / 0 | 0.300 | 0.08 |
| Entity & Temporal Integrity | 15 / 0 | 0.400 | 0.06 |

(`P(言及)` は「向きを問わず勝敗に関わった確率」、右列は「関わったとして、それが反証だった確率」。
点予測 `+1` の確率は 2 つの積 —— PB なら 0.075 × 0.25 = 0.019 でしかない。)

**ここが世界モデルの実質である。**
「Representation Coverage は 22 回決定的」だけを渡せばチェックリストになる。
「**決定的だったとき 8 回に 1 回は逆向きだった**」を同じ数値として渡せば、ならない。
Performance Belief に至っては**決定的だった 2 回とも反証**である
(Public LB を性能推定と同一視できない)。

> **点予測の argmax はこの情報を必ず捨てる。世界モデルは分布として読むこと。**

## 6. corpus が原理的に埋められない穴

| 状態 | 38 コンペ中の観測 |
| --- | ---: |
| **Hypothesis Calibration** | **0** |
| **Falsification Coverage** | **0** |

write-up は成功後に書かれ、**失敗した仮説と確信度の履歴は残らない。**
**そしてこの 2 つこそ C-lite を B から区別する構成要素である。**

> **corpus をどれだけ広げても、C-lite の価値は決まらない。実験でしか決まらない。**

縮約はこの 2 状態にも数値を返す(`p_mentioned` 0.025 / `p_minus` 0.5)。
**それは証拠ではなく事前分布である。**読み違えを防ぐため
`world_model_counterexample.json` は状態ごとに `observed` を並べ、
`unobserved_states: ["HCAL","FC"]` を明示する。

## 7. 被覆の穴 —— 8 セル中 6 セル

3 つの二値特徴で 8 セル。38 コンペが観測したのは **6 セル**である。

| セル (temporal, entity, decomposable) | コンペ数 |
| --- | ---: |
| (0,0,0) / (1,1,0) | 14 / 13 |
| (0,1,0) / (0,0,1) | 5 / 4 |
| (1,0,0) / (1,1,1) | 1 / 1 |
| **(0,1,1)** / (1,0,1) | **0 / 0** |

**NEDO は `(0,1,1)` に落ちる。**条件付き分布は全体分布へ落ちるので、
**NEDO に対する「context 条件付けの予測」はチェックリストと 1 ビットも違わない** ——
NEDO でテストできるのは**チェックリストのほう**である([予測](prediction_nedo.md) §2)。

これは装置クラス A3(**課題セットが張っていない軸は装置の盲点になる**)と**同型**で、
今回張っていないのは corpus の側、盲点は世界モデルの側にある。

なお NEDO の context 符号化自体が確かでない。規則にそのまま当たるのは `decomposable` だけで、
`entity` は行が存在しないための類推、`temporal` は課題型 `000`(オフライン並べ替え)と
`001`(到着順)で読みが割れる。**両方の読みで予測を出して点予測は同一**(RMC のみ `+1`、
`P(決定的)` 0.561)だったので登録は読みに依存しないが、**この不確かさは予測より前に書き出した。**

## 8. 使うときの規則

- **分布として読む。**点ラベルへ潰した時点で反例は消える。問い合わせは
  `scripts/predict_world_model.py` を通す(手で JSON を読まない)
- **Controller 専有。**プロンプト・契約・エージェント可視のファイルへ複製しない。
  **渡した相手で予測は検証できない**([符号化規則](coding_rules.md) §8)
- **Preferred State の既定値にしない。**符号化者が 1 名で、独立符号化の一致率が**未測定**だからである。
  実装側では `DEFAULT_PREFERRED_TARGETS` を撤去し、目標値の無い状態は **gap 0 ではなく欠測**として
  扱う(`domain/preferred_state.py`)。目標値を置くには config に `source:` が要る
- **観測 0 の状態の数値を証拠として引かない**(§6)
