# Rossmann Store Sales — 技術クラス参照物(Controller専有)

**分類:** Controller専有・エージェント非開示。[c_lite_v042_policy.md](../c_lite_v042_policy.md) §1 の
「技術クラス参照物」。discovery 後の post-hoc スコアリングにのみ使う。プロンプト・契約・
データ・エージェント可視のいかなるファイルにも複製しないこと。

**出典:** Kaggle 公開 1st place write-up(Gert Jacobusse, "Model documentation 1st place")
および Kaggle Blog の勝者インタビュー記事の要約。個別の列名・具体的コード・正確な
ハイパーパラメータは記録しない(技術クラスの水準に留める)。

## コンペの性質

ドイツの Rossmann 店舗チェーンの日次売上予測(回帰、target: `Sales`)。store・時間の
階層構造、prompt/holiday/competition 情報を含む。評価指標は RMSPE(相対誤差ベース)。

**重要な制約:** target が連続値の回帰問題であるため、本プロジェクトの Track B/v0.4.2
パイプライン(AUC ベースの preflight・decile 分割 permutation による matched negative
構築)はそのままでは適用できない。回帰用の oracle・permutation 設計は未実装
——[c_lite_v042_policy.md](../c_lite_v042_policy.md) §3 に明記の通り、今回のラウンドでは
**対象外**(見送り)。本ドキュメントは、将来 回帰対応版が実装された際にすぐ使えるよう
先行して作成した。

## 技術クラス

1. **時間・カレンダー構造への集中的な特徴量エンジニアリング。** 1st place は作業時間の
   約 50% を特徴量エンジニアリングに費やしたと述べている(祝日・曜日・プロモーション時期・
   季節性等)。
2. **店舗×時間の階層構造の利用。** 店舗属性(競合店距離・開店時期・店舗タイプ・品揃え
   カテゴリ)と時間特徴の交互作用。
3. **多数の独立に高性能な木モデルの大規模アンサンブル。** 20 以上の XGBoost モデルを
   アンサンブル。個々のモデル単体でも上位(トップ 3 相当)の性能を持つ「強い個体を集めて
   束ねる」設計であり、弱学習器を束ねるのとは異なる技術クラス。
4. **直近データへの依存度を明示的に検証する頑健性チェック。** 直近 1 か月のデータを
   除いてもほぼ同等の性能が出ることを確認しており、「短期変動への過度な依存を避ける」
   という future-holdout 感度検証の技術クラス——本プロジェクトの transfer 区間評価の
   考え方と直接関連する。
5. **(別解法として著名)カテゴリ変数の Entity Embedding。** 本コンペで最も広く引用される
   公開技術の一つとして、store id 等のカテゴリ変数をニューラルネットで埋め込みベクトル化し
   one-hot の代替とする手法(3rd place 相当の解法として発表され、後に他分野にも波及した)。
   優勝解法そのものではないが、技術クラス参照物としては記録に値する。

## 本プロジェクトでの位置づけ

回帰対応版の Suite 生成器(oracle として回帰モデルの予測値、permutation として残差または
分位点ベースの構築が必要)が実装されるまで、本コンペは v0.4.2 の実行対象外。技術クラスの
記録のみ先行して残す。
