# C-lite v0.4.8 方針 — 次のエージェント計画(実スコアを踏まえた2本立て)

**作成日:** 2026-08-31
**status:** 方針草案。基盤修正(時系列分割バグ)は実装・テスト済み。エージェント実行は
まだ行っていない——実行にはユーザーの確認を待つ。
**前提:** [v0.4.7実提出結果](verification/v047_real_submission_results.md)、
[時系列分割バグの発見](verification/v047_temporal_split_bug.md)

## 0. 出発点:実スコアが教えてくれた2つの異なる問い

[v0.4.7の実提出結果](verification/v047_real_submission_results.md)は、IEEE-CISと
Santanderで**正反対の教訓**を残した:

- **IEEE-CIS:** ローカル検証が実スコアを全く予測できなかった(ρ=-1.000)。原因を
  追う過程で、[時系列分割バグ](verification/v047_temporal_split_bug.md)——sealed
  transferが時系列的な分離を伴わないランダム分割になっていた——を発見・修正した。
  **次の問い:修正版なら、ローカル検証は実スコアを予測できるようになるか?**
- **Santander:** ローカル検証は完璧に実スコアを予測した(ρ=+1.000)。ローカルでも
  実スコアでも最良だった`agent-05-r1`、real/synthetic行判定を発見しつつ実スコアでも
  2位だった`agent-06-r1`という、**信頼できる2つの系統**が既に手元にある。
  **次の問い:この2系統をさらに深掘り(進化)すれば、実スコアはさらに伸びるか?**

この2つは性質が異なる問いなので、別々のトラックとして計画する。

## 1. Track A(IEEE-CIS):時系列分割修正の検証ラウンド

### 1.1 やること

修正済みの`_sample_split`([時系列分割バグ](verification/v047_temporal_split_bug.md)、
実装・テスト・実データ検証済み)を使って、IEEE-CISの新しいsuiteを構築する
——**コード変更は不要**(`build_v047_suite`は共有の`_sample_split`を呼ぶだけなので、
修正は自動的に反映される)。[v0.4.7と同じ12体構成](c_lite_v047_policy.md)
(sol 8体+opus 4体、low/xhigh×P1/P3、n=2ずつ)を再実行する。

### 1.2 検証する仮説

**「sealed transferが真に時系列的に分離されていれば、ローカルAUC順位は実public
score順位を予測できるようになる」**——[実提出結果](verification/v047_real_submission_results.md)で
確立した「分布シフトの有無が局所-実相関を決める」という機序から導かれる、直接
検証可能な予測。もし今回もローカルと実スコアが無相関・逆相関のままなら、
「時系列分割さえ直せば解決する」という仮説自体が誤りだったことになる
(シフトの性質がもっと複雑である可能性)。

### 1.3 実行順序

```text
v0.4.8-a1  build-only preflight(修正版suite、実データ、盲検監査)— 実施済みの
           水準まで無償で検証可能
v0.4.8-a2  12体実行(sol 8 + opus 4、v0.4.7と同一構成)
v0.4.8-a3  ローカル(修正版sealed transfer)AUCで順位付け
v0.4.8-a4  (ユーザー許可後)上位4体+ブレンドを実際にKaggleへ提出、
           local-vs-public相関を再計算——v0.4.7の ρ=-1.000 と比較する
```

## 2. Track B(Santander):実スコアで裏付け済みの2系統を深掘りする

### 2.1 やること

v0.4.7で見送った「crossover世代2」を、**今度は実スコアという本物のフィードバックを
根拠に**実施する(v0.4.7時点でこれを見送った理由——Controller自身の判断を実世界の
検証の代わりに使わない——は、実スコアが既に手元にある今は当てはまらない)。

- **親1:`agent-05-r1`**(opus P1、ローカル・実スコアとも最良、public 0.8890)
- **親2:`agent-06-r1`**(opus P3、real/synthetic行判定を発見、public 0.8857——
  僅差の2位)

既存の`scripts/run_v047_gen2_refinement.py`をそのまま使うが、プロンプトに
**実際のKaggleスコアという新しい情報**を追加する:「あなたのこのアプローチは
実際のKaggleリーダーボードでpublic score X を記録した(2競技中Y位)。この情報を
踏まえて、さらに改善できないか試みよ」——ローカルsealed transferの疑似スコア
ではなく、**本物の外部フィードバックを与えた上での改良試行**という、v0.4.7までに
なかった条件。

### 2.2 実行順序

```text
v0.4.8-b1  run_v047_gen2_refinement.pyのプロンプトに実スコア情報を注入する
           オプションを追加(小規模な実装、既存ロジック無改修)
v0.4.8-b2  agent-05-r1・agent-06-r1それぞれで実行(2run)
v0.4.8-b3  改善に成功したかをローカルで確認
v0.4.8-b4  (ユーザー許可後)改善が確認できた場合のみ、実際にKaggleへ再提出
           (5枠のうち1枠を使う想定——「今回の検証のみ」という運用方針を踏まえ、
           新たな5枠消費ではなく既存の未使用枠・または次回分として扱う)
```
