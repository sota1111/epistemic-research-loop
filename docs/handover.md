## 現在地

ERL は「KPI を改善する AI」ではなく「**未知の勝ち筋を発見する AI**」に価値があるかを
反証可能に検証するための装置である。**その検証はまだ一度も成立していない。**

理由は 2 つある。**エンジンが実運用で一度も使われていない**(唯一の campaign は
`epistemic_loop` を参照せず、別の道具一式をその場で作り直した)。そして
**C-lite の価値は winner corpus からは決まらない**ことが、38 コンペの符号化で確定した
—— Hypothesis Calibration と Falsification Coverage の観測が **0 件**だからである。

**次にやるべきことは全部** [ERL を完成させるための引き継ぎ書](v050_course_correction.md)
**の §3(残作業 12 件)と §4(順序)にある。**

## 守る制約

- **実 Kaggle / SIGNATE 提出は都度、明示承認を得る**
- **private score は比較対象にしない**
- **選定基準は機械的・事前登録されたルールのみ**(結果を見てから規則を変えない)
- **`agent/*` ブランチは成果物があれば削除しない**(独自コミット 0 の空ブランチは例外)
- 世界モデルと taxonomy は **Controller 専有**。エージェント可視のファイルへ複製しない
- 認証情報をリポジトリに置かない(`~/dev/2026/.erl-secrets/`)
- claude / codex は定額。**エージェント実行のコストを理由に躊躇しない**

## やらないこと

- リーダーボードを追って個体を足しながら、それを研究の進捗として報告すること
- 世界モデル無しで「C-lite を回した」と称すること
- 分解能を測らずに軸の効果を語ること
- **手順書を書いて成果物の代わりにすること**
