**実施:** 2026-09-06
**入力:** `erl-nedo-baggage-loading` の `results/all48/`(15 個体 × 128 課題、同一重み・同一ゲート)
**再現:**

    uv run python scripts/import_nedo_results.py \
        --results ~/dev/2026/erl-nedo-baggage-loading/results/all48 \
        --out .data/nedo/all48.jsonl --verify
    uv run erlctl measure rank --scores .data/nedo/all48.jsonl --spec .data/nedo/all48.spec.json

## 0. なぜこれを先にやったか

[引き継ぎ書](../v050_course_correction.md) §3 の 2〜4 は実装したが、**当てたのは合成データだけ**
だった。実データに当てて何も起きないなら、入れた意味はない。

NEDO の campaign は課題ごとの生ベクトルを**既に保存していた**(§3 の 4 が要求するもの)。
形式が独自だっただけである。**一度変換すれば、エンジンのゲートを実データへ向けられる。**

## 1. 変換は campaign 自身の採点を再現した

| | |
| --- | ---: |
| 取り込んだ run | 15 |
| 課題行 | 1,888 |
| 課題 | 128 |
| **各 run の composite との最大差** | **0.00000** |

採点は単なる加重和ではない。**積載率が `min_placed_fraction = 0.48` を下回った課題は、
fill 以外の全成分が 0 になる。**これを無視した加重和は campaign の順位も公表値も再現しない。
`measurement/task_scores.py` の `TaskGate` はこのゲートを**導出側**に置く ——
閾値を変えることが再採点ではなく再計算になる。

    {"weights": {"fill_score": 0.6, "cog_score": 0.2, "placement_score": 0.1,
                 "soft_item_score": 0.1, "stability_score": 0.0},
     "gate": {"metric": "num_placed_items", "minimum": 0.48, "kept_metrics": ["fill_score"]}}

### 2.2 6 体が 1 つの層に入る(順位 5〜10)

52.04 から 50.30 まで、**平均値では 6 位ぶん並んでいるが、どの対も分解できていない。**
この帯で親を順位で選ぶのは乱数を引くのと同じ、という §2.2 の主張が、
**具体的にどの 6 体かという形で出た。**

### 2.3 分解できたもの

sol 系(r3-06 / r3-07)対 opus 系、進化系対 reference / base は明確に分解できている。
**ゲートは何も言わない機構ではない。**大きい差は通し、σ の内側だけを止める。

## 3. 読むときの注意

- `shared_tasks: 96` / `planned_half_width: 3.266` は**全個体の共通課題**での値である。
  `r1-01-opus-p3-final` だけ 96 課題でしか採点されておらず、それが全体の共通集合を決めている。
  **個々の対の比較はその対の共通課題で行われる**(多くは 128、半幅 2.83)。
  ランキング全体としては**いちばん弱い対に合わせた保守的な値**を出している
- ここで比べているのは**ローカル合成**である。実 public との傾きは 0.589
  ([教訓](../v050_lessons.md) §1.2)なので、**ローカルの 2 点差は実際には 1.2 点**である。
  上の層構造は、実スコアではさらに潰れる
- **private は一切見ていない。**

## 4. 効いてくる先

- **親選定:** 首位 3 体・第 3 層 6 体は順位で選べない。課題ごとの相関(中央値 0.368)で
  相手を選ぶ設計([教訓](../v050_lessons.md) §2.2)の根拠がここで再確認された
- **ラウンド設計:** 2 点差を見たいなら課題は 256 必要(`erlctl measure plan --difference 2`)。
  **今の 128 では 2.83 点までしか分解できない**
- **腕の比較:** 個体単位でこれなら、腕平均の比較には各腕 11 体が要る
  (`erlctl measure arms --difference 6`)
