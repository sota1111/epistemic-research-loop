# v0.4.5 要因計画(DOE)結果 — 列数×フィードバック×promptアームの交絡分離

**目的:** [c_lite_v045_policy.md](../c_lite_v045_policy.md)で計画した2×2×2要因計画(F1列数{10,Full}
×F2フィードバック{None,Iterative}×F3アーム{P1,P3}、reasoning effort=xhigh固定)を実施し、
「10列制約が効いたのか、P3が効いたのか」というユーザーの問いに定量的に答える。

**実施内容(v0.4.5-c/d):** 新規4セル(C・D・E・F)を両コンペ(IEEE-CIS・Santander)で構築・
盲検監査・実行(各セルn=4×2競技=8run、計32run)。全run成功(32/32、失敗0件)、
全suite盲検監査クリーン(view・transcript計64サーフェス、検出0件)。既存4セル(A・B・G・H)は
[v0.4.4方針](../c_lite_v044_policy.md)・[v0.4.3方針](../c_lite_v043_policy.md)のデータをそのまま流用。

## 1. 応答変数1(二値):adversarial validation の出現有無 — 最も明確な結果

**P1アームは全セル・全ラウンドを通じて adversarial validation を一度も示さなかった
(A・C・E・G のいずれも0件——本セッション全体でP1が示した例は皆無)。** これにより
「P3(自己批判)が必須のゲート条件である」という結論は今回さらに補強された。

以下、**P3アーム限定**での出現率(セルB・D・F・H、列数×フィードバックの2×2表):

| | フィードバックなし | フィードバックあり(Iterative) |
| --- | --- | --- |
| **10列** | セルB: 0/41 (0%) 〔既存・確認済み〕 | セルD: 2/8 (25%) 〔新規〕IEEE-CIS 0/4・Santander 2/4 |
| **全列** | セルF: 5/8 (62.5%) 〔新規〕IEEE-CIS 2/4・Santander 3/4 | セルH: 22/22 (100%) 〔既存〕 |

(新規セルD・Fの「adversarial」該当箇所は全て approach_summary の実文を確認し、
[v0.4.3-fの無償チェック](../c_lite_v045_policy.md#5-事前の無償チェック実施済みセルbを強く確定させた)
で見つかった「context プーリング」誤検出パターンではなく、research/confirmation/transfer間の
分布シフトを判別器で検定する本来のadversarial validationであることを確認済み。)

**主効果・交互作用の解釈:**

- **列数の主効果(フィードバックなし条件で測定):** B(0%)→F(62.5%)。単独で大きい。
- **フィードバックの主効果(10列条件で測定):** B(0%)→D(25%)。単独でも正の効果があるが、
  列数単独の効果より小さい。
- **交互作用:** 加法モデルの予測値(0% + 62.5% + 25% = 87.5%)に対し、実測のH(100%)は
  それをやや上回る——**弱い正の交互作用**があり、両条件が揃って初めて「ほぼ確実に出現する」
  水準に達する。列数単独でも過半数(62.5%)まで到達することから、**列数の主効果の方が
  フィードバックの主効果より大きい**、というのが今回のデータでの最も妥当な読み。
- **セルDがIEEE-CIS 0/4・Santander 2/4と割れたこと**は、「10列+フィードバックだけでは
  安定して誘発しない」ことを示す——列数を伴わないフィードバック単独の効果は、
  コンペによって発現するかどうかが揺れる程度の弱さ、という解釈が妥当(n=4/セルなので
  この非対称自体の確度は高くないが、方向性は列数単独(セルF)の安定した62.5%と対照的)。

**結論:P3(自己批判プロンプト)は必要条件(ゲート)であり、列数とフィードバックは
P3が効いている前提の下で出現確率を押し上げる副次的な主効果(列数の方がやや強い)。**
これは元の「P3がadversarial validationを誘発する」という発見(v0.4.4-b)を、
列数・フィードバックいずれの寄与か切り分けないまま一般化していたことに対する
直接の補正であり、今回のユーザーの指摘([c_lite_v045_policy.md](../c_lite_v045_policy.md)§0)に
正確に応える結果である。

## 2. 応答変数2(連続値):自前baselineに対するtransfer AUCの上乗せ幅

各suiteは自分自身の列集合で capacity-matched baseline を再学習しているため、
生のAUCそのものより「その suite 内での上乗せ幅(uplift = agent AUC 平均 − 自 suite baseline)」の方が
セル間比較として公平。effort=xhigh に揃えた3条件(10列+FB・全列+FB・全列+noFB)で比較する
(10列+noFB は v0.4.3-f がpack/context単位の別方式でスコアリングしており、
同一baseline基準でのupliftを再構成できないため、既存ドキュメントの
「AUC範囲0.5〜0.75」という定性的な記述のみ参照する)。

| コンペ | 10列+FB (セルC/D) | 全列+noFB (セルE/F) | 全列+FB (セルG/H, xhigh分) |
| --- | --- | --- | --- |
| IEEE-CIS | baseline 0.774 → 平均0.850 (**+7.6pt**) | baseline 0.825 → 平均0.835 (**+1.0pt**) | baseline~0.836 → 平均0.859 (**+2.4pt**) |
| Santander | baseline 0.538 → 平均0.585 (**+4.7pt**) | baseline 0.835 → 平均0.901 (**+6.6pt**) | baseline~0.798 → 平均0.859 (**+6.1pt**) |

**発見:2つのコンペで「性能向上に効くレバー」が逆転している。**

- **IEEE-CIS:** 列数を10のまま feedback ループを与えるだけで最大の上乗せ(+7.6pt)が出る。
  全列を見せても feedback がなければほぼ baseline 止まり(+1.0pt)——**feedback ループの
  主効果が列数の主効果を上回る。**
- **Santander:** 逆に、feedback なしで全列を見せるだけで大きな上乗せ(+6.6pt)が出る。
  10列+feedbackはそれより小さい(+4.7pt)——**列数の主効果がfeedbackの主効果を上回る。**

これは[v0.4.4-bクロスコンペ統合分析](v044_cross_competition_synthesis.md)の発見2
(「列数を増やす効果はコンペ依存」)を、今回初めて feedback ループを独立変数として
制御した上で再確認・精緻化するものである——単に「列数を増やす効果がコンペ依存」なのではなく、
**「列数とfeedbackという2つのレバーのうちどちらが効くかがコンペ依存」**という、より具体的な
主張に更新できる。

(注:IEEE-CIS の「10列+FBがG/H全列+FBより上乗せが大きい」という結果は一見逆説的だが、
G/Hのbaseline自体がすでに全列を使っており「取れる上乗せの余地」が小さくなっている
ことの反映であり、絶対AUCで比較すればG/H(xhigh平均0.859)の方がC/D(平均0.850)より
高い。上乗せ幅は「baselineに対してagentがどれだけ追加の構造を見つけたか」を測る指標であり、
絶対的な予測性能の優劣を測る指標ではない点に注意。)

## 3. 限界

- 新規4セル(C・D・E・F)はn=4/セル/競技——[v0.4.3-fの教訓](../c_lite_v043_policy.md)通り
  単一ラウンドの数値は暫定的。特にセルDのIEEE-CIS(0/4)・Santander(2/4)の非対称は
  追加確認ラウンドで変わりうる。
- F5(エージェントモデル)は今回も未検証のまま(opus quota枯渇、既知の限界として保留)。
- F4(reasoning effort)はxhighに固定——他effortでも同じ交互作用パターンが成り立つかは未検証。
